# Smart Home Calc — дизайн-система 1.1

Статус: применяется во всех основных разделах интерфейса. Дата: 17 ноября 2026. Приложение: React 19,
TypeScript, автономная Windows-оболочка. Базовая версия интерфейса: v1.0.55.

Система объединяет план, номенклатуру, товары, редактор КП и настройки.
Основные пользователи — специалисты, которые долго работают с чертежом,
числами и большими перечнями. Главный критерий: удобство ежедневной работы.

имеют собственные профили.

## Направление

- Светлая рабочая область, белые формы и таблицы, тёмные панели инструментов.
- Зелёный акцент показывает основное действие. Синий обозначает фокус и выбор.
- Контент получает основную площадь: компактная шапка, одна прокрутка таблицы,
  постоянный доступ к добавлению и сохранению, вспомогательные настройки по запросу.
- Иконки контурные, одной толщины. У действий есть название, у переключателей — состояние.
- Одинаковые действия имеют одинаковое оформление. Состояния поясняются текстом.
- Шрифты и образец работают без интернета. В приложении нет внешних веб-шрифтов.

остаётся обозначением предмета на плане и не означает ошибку интерфейса.

## Типографика и числа

Шрифт: `Segoe UI`, затем `Inter`, `system-ui`, `sans-serif`. Segoe UI доступен
в Windows и поддерживает кириллицу. Inter используется только при наличии
на компьютере; загрузки из сети нет. Моноширинный: Consolas / ui-monospace.

| Роль | Размер | Начертание |
|---|---|---|
| Основной текст | 13 px | 400 |
| Поле, значение таблицы | 12 px | 400 / 550 |
| Значимое пояснение, статус | 11 px | 400 / 550 |
| Заголовок группы | 15 px | 650 |
| Заголовок окна | 21–24 px | 650 |
| Компактный денежный итог | 20 px | 700 |
| Заголовок документации | 32 px | 650 |

Для сумм и количества: `font-variant-numeric: tabular-nums`. Суммы выравниваются
вправо, единицы выводятся отдельно. Русский формат: `128 450,00 ₽`.
Десятичные значения принимают точку и запятую; невалидный ввод остаётся в поле
до исправления. Дробные метры не округляются при редактировании.

Это настольный интерфейс с минимальным рабочим окном 1024×700. Требование
мобильного поля 16 px не переносится на его компактные таблицы. Отдельный
образец документации адаптируется также к экрану 375 px.

## Геометрия

Шкала отступов: 2, 4, 6, 8, 12, 16, 24, 32, 48 px. Плотные значения 2 и 6
допустимы внутри таблицы. Между секциями — 16–24 px. Размеры панелей сохраняют
геометрию проверенного приложения, даже если они не кратны четырём.

| Элемент | Размер |
|---|---|
| Минимальная отдельная область нажатия | 24×24 CSS px |
| Поле / действие в строке таблицы | от 26 px |
| Обычная кнопка | от 32 px |
| Свободная форма | от 36 px |
| Иконка в строке / кнопке / панели | 14 / 16 / 20 px |
| Ширина панели иконок | 56 px |
| Панель иконок с подписями | 190 px, поверх содержимого |
| Строка панели инструментов | от 42 px |
| Левая / правая открытая панель плана | 310 / 325 px |
| Скругление поля / карточки / диалога | 6 / 8 / 12 px |

При ширине меньше 1100 px открыта одна активная панель. Наведение раскрывает
подписи, клавиатурный фокус даёт тот же доступ. Клик выбирает инструмент;
остальные секции скрываются. «Фокус на плане» скрывает и восстанавливает панели.

## Состояния компонентов

| Состояние | Правило |
|---|---|
| Обычное | Видимая подпись, спокойный фон, стабильный размер |
| Наведение | Меняются фон и граница; размер и положение сохраняются |
| Нажатие | Более насыщенный фон без скачка геометрии |
| Фокус | Контур 2 px, отступ 2 px; не перекрыт закреплённой панелью |
| Выбрано | `aria-pressed` / `aria-selected` плюс понятное выделение |
| Недоступно | Настоящий `disabled`; визуальное ослабление, действие не вызывается |
| Загрузка | Понятный текст действия и блокировка повторного запуска |
| Ошибка | Текст возле поля, `aria-invalid` и связь через `aria-describedby` |
| Неудачное сохранение | Сводка получает фокус и ведёт к нужному полю, включая другую страницу |
| Есть правки | Состояние сохраняется до успешного сохранения или явного сброса |

### Button

`variant`: secondary, primary, quiet, danger. `size`: regular или compact.
В группе один основной акцент. Удаление выделяется опасным вариантом и
подтверждается там, где затрагивает проект или черновик. Компонент сохраняет
нативное поведение формы; для отдельной команды внутри формы явно задаётся
`type="button"`, для отправки — `type="submit"`.

`ToolButton` использует Button и прежние обработчики. `ActionIcon` скрывается
от скринридера, когда рядом есть текст. Для одной иконки обязательно имя
`aria-label` и подсказка `title`. Существующие специальные размеры таблицы и
слоёв приоритетнее обычной высоты кнопки.

### Field и DecimalInput

Field связывает label, подсказку и ошибку с нативным контролом через стабильные
идентификаторы. DecimalInput продолжает отвечать за десятичные значения и
русский текст валидации. В старых формах сохраняются существующие нативные
label; замена на Field выполняется при доработке соответствующей формы.

### SearchSelect и SearchInput

Общие компоненты содержат поиск, клавиатурный выбор, Escape и размещение
списка над или под полем. Результаты фильтруются вводом и вставкой, выбранное
значение само не становится новым поисковым запросом. Развёрнутый список
сохраняет доступ к редактируемой строке.

### StatusBadge

Текстовое состояние с небольшим цветовым маркером: success / warning /
error / info. Повторяющиеся состояния не создают множество live-регионов.
Редактор КП сохраняет свой единственный `role="status"` на общей области
состояния.

## Движение и слои

Цвета и границы: 120 ms. Раскрытие панели: 180 ms. Без анимации появления
строк, пульсации кнопок и смещения редактируемых полей. При
`prefers-reduced-motion: reduce` необязательные переходы отключаются.

Уровни: закреплённая шапка таблицы 3, панель иконок 30, боковая панель 150,
модальное окно 1000, выпадающий список 2000. Токены описывают роли; локальный
stacking context учитывается при каждом переносе элемента.

## Внедрение

| Уровень | Состояние |
|---|---|
| Источник токенов, компиляция, проверка контраста | Подключены |
| Базовая палитра и шрифт приложения | Используют общие токены |
| Панели инструментов | Используют общую палитру, размеры и анимации |
| ToolButton | Использует общий Button без изменения сценариев |
| Состояние редактора КП | Использует StatusBadge |
| Поиск, числа, SVG-обозначения | Существующие компоненты включены в образец |
| План, каталог, КП, список КП, спецификация и настройки | Обновлены в VisualRefresh.css и общих Workspace-компонентах |
| PDF | Отдельный утверждённый профиль; изменения экрана на него не переносятся |

В v1.0.55 профиль применяется к основным рабочим экранам: тёмная шапка,
белая строка проекта, структурированные панели, навигация каталога и настроек,
карточки КП и компактная таблица. Структура сохранённых данных не меняется.

## Проверка и сборка

```sh
python scripts/build-design-tokens.py
python scripts/build-design-tokens.py --check
npm run build --prefix frontend
npm run design-system:preview --prefix frontend
```

Последняя команда создаёт `preview.html` в этой папке. Это один файл с
встроенными стилями и скриптами: его можно открыть на другом компьютере
без сервера, сети и установки приложения. JSON и CSS скачиваются кнопками
внутри образца. HTML воспроизводим и не хранится как вручную редактируемый код.

Браузерный сценарий `frontend/tests/design-system.cjs` проверяет работу
без сети, соответствие токенов, поиск, запятую в числах, ошибки, плотность,
клавиатурную панель, скачивание CSS, reduced motion и доступность образца
при 1440 / 1024 / 375 px. В приложении сохраняются критерии аудита:
5 полных строк КП на 1366×768 и несколько на 1024×700, 12 px в полях,
доступные нижние действия и прежний PDF.

## Применение UI/UX Pro Max

Применены проверенные рекомендации по минималистичному стилю для
профессиональных инструментов, прокрутке таблиц, контрасту, фокусу,
семантике иконок и композиции React-компонентов.

Автоподбор общей структуры дважды предложил паттерны лендингов и
несоответствующую продукту типографику. Эти части не использованы и
не выдаются за подходящий результат. Конкретная палитра, размеры и
профили экранов основаны на существующем приложении, результатах аудита
и предпочтениях пользователя. Дополнительная стилевая анимационная
библиотека для этой задачи не требуется.
